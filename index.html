Projects.

VoicePlug Inc.

DriveThru Voice Ordering Modernization

A real-time voice agent that takes DriveThru orders and files them into the POS, across multiple QSR brands. On FastAPI + Socket.IO, a speech layer streams the customer's words in, Gemini 2.5 Flash-Lite extracts menu items, an order agent replies from a cached menu-aware prompt, and a second model turns each spoken confirmation into Redis cart operations. The hard part is making a non-deterministic model safe to bill on: required-choice and per-item limit enforcement, a final cart check before submission, and staff handoff after repeated failures — deterministic code, validated against replays of real calls. MongoDB records, Jinja2 per-brand prompts, four POS integrations.

Final-Year Project | ABESIT

Mr. Healthcare - Medical Chatbot

A medical question-answering chatbot over a Neo4j knowledge graph of 658 diseases that says plainly when it cannot answer. A Vue 3 page talks to a Flask API, which finds disease and symptom names with an Aho-Corasick automaton and answers only through fixed, parameterized Cypher queries, with follow-ups (“what causes it?”), clarifying questions and suggested next questions. A language model (gpt-oss through Ollama) may read each question to handle paraphrases and negation, but it only chooses among the names the rules found and never writes an answer at question time; if it is slow or unsure, the rules answer. On a fresh, frozen set of 120 scenarios it lifted complete understanding of paraphrases and follow-ups from 54.7% to 70.9% (+16.3 points) with no new wrong-subject answers, but missed its reliability (98.1% usable replies against 99%) and latency (p95 1.56 s against 1 s) targets. Path-filtered GitHub Actions CI with a knowledge-graph gate, automatic releases and Docker images on GHCR. Live demo; not medical advice.

Open Source

Codex–Claude Council — Two AIs, One Answer

An open-source plugin and MCP server that puts one question to both ChatGPT (via the Codex CLI) and Claude (via Claude Code). They answer independently, then reply to each other round after round until they agree — one model writes the final answer while the other checks it. Built on Node.js 20+ and speaking MCP over JSON-RPC/stdio, it runs locally on your own plans by default; either side can take an API key instead, or skip its CLI and run through the OpenAI or Anthropic API. It works across Claude Code, Codex, Claude Desktop and the ChatGPT app. On a 24-question benchmark of deliberately tricky programs, run from fresh sessions with no web search, it scored 24/24, matching the best single model while catching the other's one miss.

Global InfoVentures Pvt. Ltd. | Team project

Conversational AI for College ERP

A voice- and text-driven assistant that answers questions against live college ERP data across multiple client institutes. Audio is transcribed server-side through a FastAPI gateway, then a two-stage Rasa router picks the ERP module — asking a clarifying question and re-classifying when confidence is low, so an ambiguous query never reaches the LLM. Schema grounding is the hard part: each institute's hundreds of field mappings are embedded into Milvus and retrieved alongside similar few-shot examples, so Gemini 2.5 Flash emits constrained SQL fragments into a fixed payload contract instead of free-form SQL. The ERP executes it and a second model summarises the rows.

Global InfoVentures Pvt. Ltd.

PTZ Classroom Attendance — One Camera per Room

Classroom attendance from a single PTZ camera per room instead of a wall of fixed cameras. The system drives one ONVIF camera through a timed preset sweep — dedicated faculty captures at lecture start and end, then a 23-preset trace across the seats — with zoom and focus settling budgeted into every hop. Frames go to a TensorRT-backed InsightFace-REST service for detection and embedding, and identities come from a top-1 Milvus search over 512-d vectors. A separate YOLOv9 service counts heads independently; the two are reconciled per lecture and synced to the institute ERP. Four Dockerised services on a MIG-partitioned GPU, with PostgreSQL attendance logs.

Global InfoVentures Pvt. Ltd.

CCTV Face Recognition Attendance — Multi-Stream

The multi-stream sibling to the PTZ system. A producer process decodes 20+ live RTSP camera feeds — ROI crop and lighting check per frame — into a shared in-memory queue; a consumer batches 32 frames per request to InsightFace-REST, running as two TensorRT replicas on separate MIG slices behind nginx, where SCRFD (scrfd_10g_gnkps) detects and w600k_r50 embeds. Identities resolve by cosine search over a GPU-indexed Milvus collection. The gallery improves itself: high-confidence crops land in a staging collection that a nightly job folds into the index. Results persist to PostgreSQL, sync to the institute ERP, and stream back to on-site displays over Kafka.

Personal Project

Clinic Voice Receptionist — Multilingual Voice Booking

An inbound voice agent for dental clinics, built against a real published brief, that books appointments in English, Hindi, Tamil, Kannada and Malayalam and follows up over WhatsApp. On FastAPI, a local Whisper model on the GPU transcribes each turn, an LLM slot extractor (LangChain + Ollama, with a rule-based fallback) pulls out the booking details, and Piper and MMS-TTS speak the reply — 0.8–1.0 s per turn on an RTX 4050. The rule that matters: details it heard with low confidence are read back to the caller before anything is booked. On its own 11-utterance test set with simulated transcription errors up to 50%, accuracy falls to 74.4% but no wrong detail goes unflagged. Telephony (Bolna), WhatsApp (AiSensy) and n8n routing are built against their documented payloads.

Personal Project

AgencyOps Orchestrator — Agentic Workflows, Human Approval

Agentic workflow automation for an eCommerce marketing agency, built against a real published brief: it drafts weekly client performance reports and ad-creative variants. LangGraph state graphs with bounded revise loops do the drafting, and nothing reaches a client or an external tool until a person approves it in a FastAPI review console — workflows only propose external writes, and one dispatch path runs them after approval. All arithmetic is deterministic Python; the LLM (Ollama or Gemini, with an offline fallback) only writes the prose, and a verify gate rejects any narrative that contradicts the numbers, such as “CPA fell” when it rose. Meta Ads, Harvest, Slack and Trello connectors; the demo and tests run offline with no credentials.

Personal Project

Dubai Smart Irrigation Advisor — Ranked by Cost, Not Error

Built against a real published brief, it decides when to irrigate in Dubai's desert climate, and ranks six predictors by what they cost to run in AED rather than by prediction error. The physics core is FAO-56 Penman–Monteith ET0 with a root-zone soil water balance; it reproduces FAO-56's worked examples exactly and agrees with published Dubai climate normals to 2.3% over 30 years of NASA POWER data. Against it run scikit-learn, XGBoost and PyTorch LSTM/GRU models, each scored by what its decisions cost in water and AED over a simulated 120-day season. The best learned model comes within 5% of the physics baseline, which also drives the simulator; acting on the raw soil sensor alone costs 6.7 times as much. A Streamlit dashboard shows the decisions, with optional plain-language explanations from a local LLM whose every number is checked against the facts.

Personal Project

Career Growth AI for Kids — Built for Children's Data

A web app, built against a real published brief, where parents build profiles for their children — age band, grade, interests and strengths — and get AI-generated career-exploration ideas. Children never log in, and parents own all the data. FastAPI with async SQLAlchemy over PostgreSQL, a React 19 + TypeScript front end, and an Ollama-served model. The care went into handling children's data: a child's name and the parent's notes are never sent to the AI (tests enforce it), only the birth year is stored, and a parent asking for another parent's child gets a 404. Auth uses short-lived JWTs in httpOnly cookies and hashed, rotating refresh tokens — reuse one and every session is revoked — with per-user rate limits on login and AI generation.

Internship | Global InfoVentures Pvt. Ltd.

PPE Violation Detection

A browser-based PPE monitor: point it at an uploaded clip or a live camera URL and it streams the raw and annotated feeds back side by side over MJPEG. A custom-trained YOLOv7 model classifies every person in frame as compliant or violating at a 0.75 confidence gate, and a temporal rule waits for a run of unsafe frames before firing — so one stray detection doesn't page anyone. When it does fire, the Gmail API emails the offending frame to a configured recipient as evidence, then holds a cooldown before the next alert. Flask, OpenCV and PyTorch on CPU, with per-run detection reports exportable from the UI as a timestamped log.

HalalLens — Halal Investment Research Copilot

A full-stack Shariah-compliance screener for BSE-listed Indian equities. A FastAPI backend (39 REST endpoints) and a Next.js 16 static front end sit over PostgreSQL, with an AAOIFI-style ratio engine that answers compliant, non-compliant or insufficient data, so partial figures never pass as compliant. The “Explain Why” narrator runs on deterministic rules by default, each verdict citing the filing date and the figures it was computed from, with an optional vLLM / OpenAI-compatible mode behind a config flag. Automatic releases publish multi-arch Docker images, Trivy-scanned with SBOM and provenance, and a health-checked script deploys them to an Oracle Cloud VM behind a Cloudflare Tunnel; 806 backend tests in CI, plus opt-in real-Postgres tests that prove the race-condition fixes. Production holds no BSE filings yet, while a permitted data source is pending.
